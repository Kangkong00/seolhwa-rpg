## 프로젝트 개요

바람의나라처럼 사냥하며 성장하는 2.5D RPG를, 아이폰에서 혼자 즐기는 버전부터 만듭니다. 재미가 확인되면 서버를 붙여 여러 명이 함께 하는 MMO로 넓힙니다.

| 항목 | 내용 |
|---|---|
| 장르 | 성장형 RPG (최종 목표 MMORPG) |
| 참고 게임 | 바람의나라, 도깨비의 세계 |
| 세계관 | 전통 설화풍 (나중에 바꿀 수 있음) |
| 화면 | 2.5D, 3/4 탑다운, 반실사 고품질 2D 그림 |
| 플레이 기기 | 아이폰 가로 화면 (PC 브라우저도 실행 가능) |
| 직업 | 1개로 시작 |
| 핵심 재미 | 사냥 → 아이템 드랍 → 레벨업·무기 강화 → 더 강한 사냥터 |
| 역할 분담 | 강콩: 방향 판단, 그림 생성(Flow), 최종 검토 / 기획 대화의 Claude: 기획서, 프롬프트, 그림 가공, 저장소에 그림·지침 업로드 / Claude Code: 코드 |

**개발 원칙**

- 재미 먼저, 통신은 나중: 혼자 해도 재밌는지를 먼저 확인합니다. MMO의 어려움은 대부분 통신에서 생기기 때문입니다.
- 게임 규칙과 화면 그리기를 분리: 나중에 서버를 붙일 때 처음부터 다시 만들지 않기 위해서입니다.
- 그림은 갈아 끼울 수 있게: 그림 파일만 바꾸면 게임 전체 모습이 바뀝니다. 그림 때문에 개발이 멈추지 않게 하려는 것입니다.
- 수치는 코드가 아니라 표에: 몬스터 능력치, 드랍 확률, 강화 확률은 데이터 파일로 따로 뻑니다. 코드를 몰라도 강콩님이 직접 조정할 수 있게 하려는 것입니다.
- 한 번에 하나씩: 각 단계는 완료 기준을 통과해야 다음으로 넘어갑니다.

## 기술 구조

웹 기술로 만들고, 아이폰에서는 홈 화면에 추가해 앱처럼 실행합니다. 앱스토어 등록 없이 바로 쓸 수 있고, 나중에 서버(Node.js)도 같은 언어로 붙일 수 있습니다.

| 구성 | 선택 | 이유 |
|---|---|---|
| 언어 | 자바스크립트 | 기존에 만든 HTML 도구들과 같은 방식, 서버도 같은 언어 |
| 게임 엔진 | Phaser (웹용 2D 엔진) | 그래픽 가속으로 고해상도 그림을 아이폰에서 부드럽게 돌림. 버전은 개발 시작 시 확인 필요 |
| 맵 편집 | 자체 격자 편집 화면 (단계 3에서 제작) | 통그림 위에 "갈 수 있는 칸 / 못 가는 칸"만 칠하면 되도록 |
| 저장 | 기기 안에 자동 저장 (혼자 하는 단계) | 아이폰은 앱이 수시로 꺼지므로 변화가 있을 때마다 저장 |
| 백업 | 저장 파일 내보내기·불러오기 | 아이폰이 기기 저장을 지울 수 있어서(확인 필요) |
| 수치 데이터 | 몬스터·아이템·드랍·강화 표를 별도 파일로 | 코드 수정 없이 밸런스 조정 |
| 배포 | GitHub Pages (확정) | 아이폰 사파리에서 주소로 접속 → 홈 화면 추가 |
| 코드 관리 | GitHub 저장소, 기능별로 여러 파일 (확정) | 게임이 커지면 HTML 파일 하나로는 관리가 어려움. 변경 기록도 남음 |

**폴더 구조 (초안)**

```
seolhwa-rpg/
  index.html            게임 시작 페이지
  src/
    core/               게임 규칙 (전투 계산, 드랍, 강화, 레벨업) — 화면과 무관
    scenes/             화면 (마을, 사냥터, 가방, 강화창)
    ui/                 조이스틱, 버튼, 체력바
    save/               저장·불러오기
  data/                 수치 표 (monsters, items, drops, enhance, levels)
  assets/
    characters/         주인공·NPC 그림
    monsters/
    maps/               통그림 맵 + 격자 정보 + 지붕 등 위쪽 레이어
    items/              아이콘
    effects/            타격·잔상 이펙트
  docs/                 이 계획서의 복사본, 설계서
```

**서버 확장 대비** — `core/`는 화면 코드를 하나도 모르게 만듭니다. MMO 단계에서는 이 폴더를 그대로 서버로 옮겨 전투 판정을 서버가 하게 합니다. 이렇게 해야 게임을 속이는 조작(해킹)을 막을 수 있습니다.

## 마을 배치도

마을은 한 맵에 모든 시설을 넣습니다. 지붕은 비슷해도 마당에 놓인 물건으로 건물마다 특색을 줍니다. 던전 입구는 시설 뒤편과 생활 공간에 숨겨 두어 찾아가는 재미를 살립니다.

## 그림 제작 규칙

그림은 Google Flow로 만들고, 부족한 동작은 코드로 보정합니다. 걸기 테스트에서 같은 인물 유지는 합격, 다리 동작은 코드 보정으로 해결되는 것을 확인했습니다.

부위별 프롬프트와 제작 현황은 [설화 RPG 그림 프롬프트 모음](https://claude.ai/code/artifact/85967246-5bab-4ad7-8766-d0af60309e2f)에서 관리합니다.

**기준 그림** (새 그림은 항상 이 그림을 @에셋으로 참조)

- 배경 기준: 초가 마을 전경
- 캐릭터 기준: 주인공 v2 (상투, 남색 도포, 환도, 2.5~3등신)
- 몬스터 기준: 꼬마 도깨비 v2

**생성 규칙**

- 동작은 한 장씩 따로 생성합니다. 여러 장을 한 번에 뽑으면 왼발·오른발을 헷갈립니다.
- 항상 단색 흰색 배경, 그림자 없음, 글자 없음("FRONT VIEW" 같은 글자도 빼기).
- 여러 캐릭터를 한 장에 넣을 때는 "캐릭터 사이 간격 넓게"를 넣습니다. 칼끝이 옆 칸으로 넘어가면 잘라내기 어렵습니다.
- 스크린샷이 아니라 Flow에서 원본 파일로 다운로드합니다.
- 맵은 가장 큰 해상도로 생성합니다. 1.6배 확대하면 지금 마을 그림(가로 1376픽셀)은 살짝 흐려집니다. 부족하면 마을을 구역으로 나눠 따로 뽑습니다.
- 워터마크(오른쪽 아래 ✦)가 있으면 사용 전에 지웁니다.

**코드로 보정하는 것** (Claude 담당)

- 흰 배경 제거, 발 위치 기준선 맞추기
- 걸기: 서 있기 + 한 발 내밀기 → 다리 좌우 반전으로 반대 발 제작, 발 딛을 때 몸 살짝 띄우기
- 왼쪽 방향: 오른쪽 그림 좌우 반전
- 타격감: 잔상, 번창임, 화면 흔들림, 피격 시 몬스터 밀려남
- 지붕 가림: 지붕 부분만 오려서 캐릭터 위에 한 겹 더 올림

**캐릭터 한 명당 필요한 그림**

| 동작 | 정면 | 뒷면 | 오른쪽 | 상태 |
|---|---|---|---|---|
| 서 있기 | 1장 | 1장 | 1장 | 주인공 완료 |
| 한 발 내밀기 | 1장 | 1장 | 1장 | 정면만 확보 |
| 공격 준비 | 1장 | 1장 | 1장 | 미제작 |
| 휘두르기 | 1장 | 1장 | 1장 | 미제작 |
| 맞음·쓰러짐 | 1장 | - | - | 미제작 (정면 1장으로 대체) |

주인공은 약 13장, 몬스터는 종류당 약 7~9장(뒷면 생략 가능)입니다. 무기를 바꿀 때마다 캐릭터 그림을 다시 뽑을지는 단계 4에서 정합니다.

## 개발 로드맵

*(도표: 개발 로드맵 · 8단계, 단계마다 완료 기준 — 원본 문서에서 확인)*

지금은 단계 0의 마지막 그림 테스트 중입니다. 단계 1까지는 문서 작업이고, 실제 코드는 단계 2부터 시작합니다. 단계별 기간은 정하지 않고, 완료 기준 통과 여부로만 넘어갑니다.

## 단계별 체크리스트

각 단계의 마지막 항목이 완료 기준입니다. 완료 기준은 강콩님이 직접 해보고 판정합니다.

### 단계 0 — 방향 정하기·그림 검증

- [x] 개발 순서 확정 (혼자 하는 RPG 먼저)
- [x] 시점 확정 (3/4 탑다운)
- [x] 세계관 확정 (전통 설화풍)
- [x] 그림 도구 검증: 마을·주인공·도깨비 v2 합격
- [x] 맵 위에 캐릭터 올려보기, 카메라 1.6배 확정
- [x] 걸기 동작 테스트: 같은 인물 유지 합격, 다리는 코드 보정으로 해결
- 한 발 내밀기 단독 생성 테스트 (뒷면·옆면)
- 공격 동작 2장 테스트
- 완료 기준: 주인공이 네 방향으로 걷고 한 방향으로 공격하는 그림이 모두 확보됨

### 단계 1 — 게임 설계서

- 핵심 반복 구조 (사냥 → 드랍 → 성장 → 다음 사냥터)
- 능력치 종류와 역할 (힘, 체력 등)
- 레벨별 필요 경험치 곡선 (1~30)
- 전투 계산식 (피해량, 명중, 치명타)
- 첫 사냥터 몬스터 3종 능력치
- 아이템 등급 (일반·고급·희귀·전설)과 드랍 표
- 무기 강화 규칙 (+1~+10, 성공 확률, 실패 시 처리)
- 골드 들어오는 곳·나가는 곳
- 완료 기준: 강콩님이 수치를 보고 "이 정도면 해보고 싶다"고 판단

### 단계 2 — 움직이는 시제품

- 프로젝트 폴더·저장소 만들기
- 마을 통그림 맵 표시 + 카메라 따라가기
- 가로 화면 고정, 아이폰 화면 비율 대응
- 왼쪽 가상 조이스틱으로 4방향 이동
- 걸기 동작 (코드 보정 방식 적용)
- 못 가는 칸 (집·담장) 막기
- 지붕 뒤로 지나갈 때 가려지기
- 아이폰 홈 화면 추가 테스트
- 완료 기준: 아이폰에서 마을을 끊김 없이 걸어 다닐 수 있음

### 단계 3 — 사냥 핵심

- 사냥터 맵 1개 + 마을과 맵 이동
- 도깨비 등장·배회·추격·공격
- 주인공 기본 공격 + 타격 이펙트
- 체력바, 피해 숫자 표시
- 경험치·레벨업
- 몬스터 다시 나타나기
- 주인공 쓰러짐 → 마을에서 부활
- 맵 편집 화면 (갈 수 있는 칸 칠하기)
- 완료 기준: 10분 동안 사냥해도 지루하지 않음

### 단계 4 — 아이템·성장

- 아이템 드랍 (등급별 색깔·빛 효과)
- 가방 화면
- 장비 착용 (무기·방어구)
- 무기 강화 화면 + 성공·실패 연출
- 대장간·상점 NPC
- 자동 저장 + 저장 파일 내보내기
- 무기 변경이 캐릭터 그림에 보이는 방식 결정
- 완료 기준: 1시간 플레이 후 다음 날 또 하고 싶음

### 단계 5 — 콘텐츠 확장

- 사냥터 3단계 (초급·중급·고급)
- 몬스터 6~9종 + 보스 1종
- 스킬 3~4개
- 간단한 퀘스트 (처치·수집)
- 완료 기준: 레벨 30까지 자연스럽게 올라감

### 단계 6 — 다듬기

- 효과음·배경음악 (저작권 확인된 것만)
- 처음 하는 사람용 안내
- 아이폰 배터리·발열 점검
- 완료 기준: 2주 동안 매일 하고 싶음

### 단계 7 — MMO 전환 (검토 단계)

- 서버·비용 검토 (확인 필요)
- 계정·로그인
- 여러 명 동시 접속, 서로 보이기
- 전투 판정을 서버로 이전
- 채팅
- 완료 기준: 지인 몇 명과 같이 사냥해도 끊김·오류 없음

## 문서 운영 규칙

이 문서가 프로젝트의 기준입니다. 채팅이 바뀌어도 이 문서 링크 하나로 이어갑니다.

- 새 채팅을 열면 이 문서 링크를 먼저 붙여넣습니다. Claude는 "지금 할 일"과 "확정 사항"을 읽고 이어서 작업합니다.
- 대화가 끝날 때 Claude가 세 곳을 갱신합니다: 지금 할 일, 체크리스트 체크, 결정 로그 한 줄.
- 결정이 바뀌면 "확정 사항" 표를 고치고, 이전 결정은 기각안 칸으로 옮깁니다. 같은 논의를 다시 하지 않기 위해서입니다.
- 확인되지 않은 내용은 "확인 필요"로 표시합니다.
- 문서가 커지면 다음을 별도 문서로 분리하고 여기서는 링크만 겁니다: 게임 설계서(수치), 그림 프롬프트 모음, 세계관·스토리.
- 코드 작업을 시작하면 이 문서의 복사본을 프로젝트 `docs/` 폴더에도 둡니다. 코드 쪽 작업자가 같은 기준을 보게 하려는 것입니다.
