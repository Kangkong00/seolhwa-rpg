## 2. 여우굴: 여우가 바닥이 아닌 곳을 걸음 → 격자 고침 (기획 쪽, 반영됨)

- `node tools/test/mapcheck.mjs` 모든 맵 좋음.

## 3. 여우굴 → 구미호의 방으로 못 들어감 (원인 확인 필요 → Claude Code)

- 저장소 데이터로는 들어갈 수 있음: 게임의 `isStandable`·`footBox`로 1px마다 칠해 보니 입구 사각형 안에 갈 수 있는 자리 2,037곳, 모든 맵의 입구·도착 자리도 이어짐.
- **가장 의심되는 원인: 이 기기에 남은 옛 격자 편집(G)**. `loadMap()`은 `localStorage`의 `seolhwa-rpg:grid-edit:<맵>`이 크기만 같으면 저장소 격자 대신 씀 → 10-19 초안 때 G로 고친 내용이 남아 있으면 10-20·10-22에 새로 만든 정밀 격자가 **그 기기에서는 적용되지 않음**. "고쳤다는데 또 그렇다"와 맞음. (강콩이 여우굴에서 G를 쓴 적이 있는지 확인 필요)
- 그래서 격자 편집을 **저장소 격자와 짝지어** 저장하게 바꿈(아래 Claude Code 할 일 1).

## Claude Code 할 일

1. **격자 편집을 저장소 격자와 짝짓기**: 저장할 때 `{ base: <저장소 blocked의 짧은 해시>, rows }`. 불러올 때 `base`가 지금 저장소 격자와 다르거나 옛 모양(배열만)이면 **쓰지 않고 지움**, 화면에 한 번 "이 기기의 옛 격자 편집을 지웠습니다(새 맵 격자 사용)".
2. **관리자 창 설정 탭**: "이 기기 격자 편집" 줄 — 편집이 남은 맵 이름과 「모두 지우기」 단추.
3. **`tools/test/mapcheck.mjs` 입구 검사를 정확하게**: 지금은 입구 둘레 ±8px 안의 갈 수 있는 자리도 "들어감"으로 셈 → 입구 사각형 **안**에 발이 설 수 있는 자리가 있는지로(기획 쪽 확인 스크립트와 같은 방식). 도착 자리(arrive)가 다른 입구 사각형 안이 아닌지도.
4. **몬스터가 바닥 위에 있는지 시험**: `chaos.mjs`(또는 `monsterwalls.mjs`)에서 프레임마다 모든 몬스터 발 상자(`bodyBox`)가 `isStandable`인지 — 여우굴 1층·구미호의 방 각각 2분, 0건이어야 함. 여우불(날아가는 것)은 빼고.
5. **무기 쥐는 점 시험**(브라우저 없이): `data/weapons.json` 모든 무기 그림에서 750~800줄 손잡이 가운데가 120±4인지, 왼쪽·오른쪽 끝 열에 칼날이 닿지 않는지. 새 무기 그림이 와도 이 시험으로 걸러짐.
